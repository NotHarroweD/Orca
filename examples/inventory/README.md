# Worked example: stack limits for an inventory

One task, start to finish, so you can see what the artifacts look like when the loop actually runs.
The scenario is SPEC-003 from the running example in the guide.

Read in order:

1. [`01-spec.md`](01-spec.md): what the orchestrator hands the implementer
2. [`02-implementer-report.md`](02-implementer-report.md): the first attempt, which looks fine
3. [`03-review.md`](03-review.md): the independent review, which finds a real problem
4. [`04-fix-and-accept.md`](04-fix-and-accept.md): the fix, the second review, and the record

The point: every automatic check passed on the first attempt, and the work was still wrong.
The review caught it because the reviewer looked at the result instead of the report.
